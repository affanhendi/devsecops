RINGKASAN EKSEKUTIF

Praktikum Bab 6 bertujuan membangun sistem centralized logging pada aplikasi Penerimaan Mahasiswa Baru (PMB) berbasis kontainer. Aplikasi terdiri dari enam layanan: registration-api, auth-service, verification-worker (aplikasi), app-db (database transaksi), log-db (database log terpusat), dan fluent-bit (collector log). Semua log stdout/stderr dari layanan aplikasi dikirim melalui Docker logging driver fluentd ke Fluent Bit, lalu disimpan ke PostgreSQL dalam tabel logs.fluentbit dengan kolom tag, time, dan data JSONB. Dari hasil praktikum, seluruh layanan berjalan dengan status sehat (Up / healthy). Tiga alur uji berhasil dieksekusi: 1. Alur normal (mode none): Pendaftaran berstatus VERIFIED. 2. Alur insiden (mode timeout): Worker mencoba verifikasi tiga kali, lalu gagal dengan dependency_timeout dan status FAILED (VERIFY-TIMEOUT). 3. Recovery: Setelah dikembalikan ke mode none, pendaftaran baru berhasil diverifikasi menjadi VERIFIED; pendaftaran lama yang FAILED tidak berubah secara otomatis. Pengujian keamanan log menunjukkan nol temuan kata sensitif (password, authorization, bearer, cookie, session secret, API key) pada payload log. Metrik Fluent Bit mencatat 217 record masuk, 0 error, 0 retry gagal, dan 0 record yang dibuang. Seluruh target verifikasi PASS/FAIL dari cheatsheet Bab 6 telah terpenuhi. ---

1. TUJUAN PRAKTIKUM

Berdasarkan modul Bab 6, setelah menyelesaikan praktikum ini, mahasiswa diharapkan mampu: 1. Menjelaskan kebutuhan centralized logging pada lingkungan container yang ephemeral. 2. Mengirim log stdout/stderr container ke Fluent Bit menggunakan Docker logging driver fluentd. 3. Menyimpan log ke PostgreSQL dalam kolom JSONB dan membuat view analisis. 4. Menerapkan query pencarian log dan retention sederhana. 5. Menguji retry, timeout, buffering, recovery, dan kemungkinan kehilangan log. ---

8. KESIMPULAN

Praktikum Bab 6 menggunakan laboratorium pmb-devsecops-lab (versi 1.0.0) berhasil membangun sistem centralized logging dengan Fluent Bit dan PostgreSQL. Log dari tiga layanan aplikasi ( egistration-api, uth-service, erification-worker) berhasil dikumpulkan melalui Docker logging driver luentd, disimpan dalam kolom JSONB pada tabel logs.fluentbit, dan dapat dianalisis menggunakan query SQL. Hasil utama: - Enam layanan berjalan dengan status sehat (Up / healthy). - Alur normal menghasilkan status VERIFIED; alur insiden timeout menghasilkan tiga retry lalu dependency_timeout dan status FAILED. - Recovery berhasil: transaksi baru menjadi VERIFIED setelah mode dikembalikan ke one; transaksi lama FAILED tidak berubah otomatis. - Tidak ada kredensial atau data sensitif yang bocor ke log (0 temuan secret). - Metrik Fluent Bit mencatat 217 record, 0 error, 0 retry gagal, 0 record dibuang. - Seluruh target verifikasi PASS/FAIL terpenuhi. Arsitektur ini cukup baik untuk kebutuhan laboratorium dan pembelajaran, namun sebelum diterapkan pada produksi-like environment, diperlukan penambahan secret management, TLS, pembatasan akses monitoring, kebijakan retensi, dan uji recovery berkala. ---
